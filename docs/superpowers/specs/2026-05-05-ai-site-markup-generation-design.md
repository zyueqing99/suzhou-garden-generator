# 场地图标注驱动的 AI 方案生成重构设计

## 背景

当前应用的第二版原型围绕“场地解析、需求确认、园林规则、方案生成”组织工作台，并使用规则 SVG 作为中间产物，再由用户继续导出或触发 AI 出图。实际验证后，SVG 中间产物的表现力和可用性不足：它既不能充分承载真实场地图约束，也让用户流程变成“先生成抽象平面，再生成概念图”的绕路。

本次重构的业务目标不是单纯拆分组件，而是替换生成链路：用户直接在放大的场地图上完成标注，应用把带标注的场地图截图、场地解析 JSON、生成控制参数和内置苏州园林规则一起发送给 `gpt-image-2`，由 AI 直接生成景观概念方案图。

## 目标

- 删除用户可见的 SVG 中间步骤，主流程不再依赖 SVG 平面图。
- 上传场地图后，在右侧主窗口的大图状态下进行标注。
- 支持地块边界、建筑轮廓、主入口、景观方向四类标注。
- 标注可以修改、清除和重画。
- 左侧保留生成控制，用户确认标注和参数后触发 AI 出图。
- 生成请求包含带标注场地图截图、场地解析 JSON、生成控制参数和内置苏州园林规则。
- 右侧主窗口用标签页切换 `场地标注`、`生成方案`、`方案说明`。
- 方案文字说明先由本地规则生成，后续预留替换为文本模型 API 的边界。

## 非目标

- 不在本次接入文本模型 API。
- 不保留 SVG 作为用户可见预览、导出或生成步骤。
- 不重写项目持久化体系；只在现有 `GardenProject` 结构上做必要字段调整或兼容迁移。
- 不把标注工具做成专业 CAD 编辑器；本次只需要满足方案生成前的约束表达。
- 不改变 VectorEngine 代理的密钥隔离方式。

## 新业务流程

1. 用户打开应用。
2. 用户上传场地图。
3. 右侧主窗口进入 `场地标注` 标签，放大展示场地图。
4. 用户在放大的场地图上选择工具并标注：
   - 地块边界：多点多边形。
   - 建筑轮廓：多点多边形。
   - 主入口：单点标记。
   - 景观方向：方向标记。
5. 用户不满意时可以清除当前工具标注并重画。
6. 用户在左侧调整生成控制参数。
7. 用户点击生成方案。
8. 应用截取右侧带标注场地图，生成场地解析 JSON，并组合内置苏州园林规则提示词。
9. 应用调用 `gpt-image-2` 生成景观概念图。
10. 生成成功后右侧主窗口切到 `生成方案` 标签。
11. `方案说明` 标签展示本地规则生成的文字说明。

## 页面信息架构

页面保留工作台形态，但中心从 SVG 方案画布改为场地图和 AI 结果。

左侧区域包含：

- 项目历史与新建项目。
- 场地图上传入口。
- 标注工具：地块边界、建筑轮廓、主入口、景观方向。
- 当前标注摘要和清除操作。
- 生成控制：水景比例、山石比例、植物密度、风格、主要元素、随机种子等。
- 生成方案按钮。
- 导出 PNG 和 JSON。

右侧主窗口包含：

- `场地标注` 标签：显示放大后的场地图和标注覆盖层，是唯一的标注操作区域。
- `生成方案` 标签：显示 `gpt-image-2` 返回的方案图、生成状态和失败提示。
- `方案说明` 标签：显示总体布局、功能分区、动线、景观节点、苏州园林手法、落地提醒和输入摘要。

## 标注交互

标注动作必须发生在右侧 `场地标注` 标签的大图上。左侧可以展示工具、状态和清除按钮，但不提供小图标注。

地块边界和建筑轮廓使用连续点击生成点集。点数达到 3 个后，界面以闭合多边形显示。继续点击会追加点，用户可以通过清除当前工具重新绘制。

主入口使用单点标记。再次点击会替换旧入口点。

景观方向使用单点方向标记：用户点击建筑主观景面或主要借景方向所在位置，系统把点位换算成方位文案，并在覆盖层上显示方向标识。导出的解析 JSON 必须保存原始点位和推导后的方位文案。

标注覆盖层需要被截图保留下来，作为 AI 图像生成的视觉约束。截图对象是右侧放大场地图区域，不是原始图片，也不是旧 SVG 画布。

## 生成输入

点击生成方案时，前端构造一个 AI 图像生成请求。请求由四部分组成：

1. 带标注场地图截图：来自右侧 `场地标注` 大图区域。
2. 场地解析 JSON：由标注数据推导，包括地块边界、建筑轮廓、主入口、景观方向、相邻界面和遮挡建议。
3. 生成控制参数：水景比例、山石比例、植物密度、风格、构筑物偏好、路径曲率、焦点空间、随机种子等。
4. 内置苏州园林规则：强调曲径通幽、障景、借景、框景、漏景、叠石理水、入口收放、水院展开和茶庭收束等设计原则。

`buildImagePrompt` 需要从“描述 SVG 方案”改为“解释带标注场地图约束，并指导 AI 输出景观概念方案图”。`buildAiImageRequest` 继续负责把参考图和 prompt 传给 VectorEngine 代理。

## 方案说明

本次不接入文本模型。方案说明由本地规则生成器产生，输入包括：

- 场地解析 JSON。
- 生成控制参数。
- 内置苏州园林规则。
- AI 生成状态和当前项目名称。

说明结构固定为：

- 总体布局说明。
- 功能分区说明。
- 动线说明。
- 景观节点说明。
- 苏州园林手法。
- 周边关系回应。
- 可落地性提醒。

后续接入文本模型 API 时，新增文本说明服务替换本地说明生成器即可，页面结构和导出结构不需要重写。

## 数据与导出

已有 `siteMarkup` 继续作为标注数据基础：`boundary` 保存地块边界点集，`buildingFootprint` 保存建筑轮廓点集，`mainEntrance` 保存主入口点位，`mainViewSide` 保存景观方向点位。场地解析 JSON 在此基础上生成方位文案和遮挡建议。

PNG 导出改为导出 AI 方案图或当前生成结果图，不再导出 SVG。

JSON 导出包含：

- 项目信息。
- 原始标注数据。
- 场地解析 JSON。
- 生成控制参数。
- AI 图像请求摘要。
- AI 生成记录。
- 本地生成的方案说明。

SVG 导出从用户界面移除。

## 组件与边界

本次重构可以在现有 React 架构内完成，不以拆文件为主要目标，但需要让业务边界清楚：

- 场地图标注视图负责展示大图、收集点位、渲染标注覆盖层和提供截图目标。
- 生成控制负责编辑参数。
- AI 生成编排负责截图、构造解析 JSON、构造 prompt、调用图像接口和保存生成记录。
- 方案说明生成器负责把结构化输入转成固定栏目文本。
- 导出逻辑负责导出 AI 结果图和 JSON 数据。

旧的规则 SVG 预览、SVG 导出和以 `generateGardenPlan` 为核心的用户可见流程应从工作台移除。若部分规则算法仍可为 prompt 提供文字参考，只能作为内部规则文本来源，不能重新变成用户流程里的 SVG 中间产物。

## 错误处理

- 未上传场地图时，生成按钮不可用，并提示先上传场地图。
- 未完成关键标注时，生成前给出明确提示。关键标注至少包括地块边界、建筑轮廓和主入口。
- 截图失败时，保留用户标注状态并提示重新生成。
- AI 图像生成失败时，保留请求摘要和错误信息，用户可以修改标注或参数后重试。
- 已有旧项目如果存在 SVG 生成记录，不影响打开；页面只展示可用的场地图、标注、AI 生成图和说明。

## 测试策略

测试重点从 SVG 存在性转向业务流程：

- 渲染三标签：`场地标注`、`生成方案`、`方案说明`。
- 未上传场地图时显示上传引导，生成按钮不可用。
- 上传场地图后，右侧大图区域成为标注区域。
- 四类标注工具存在，且标注信息只在右侧大图区域产生。
- 清除当前工具标注后，对应标注数据被移除。
- 生成请求包含带标注图片、场地解析 JSON、生成控制参数和园林规则 prompt。
- 生成成功后切换到 `生成方案` 标签。
- 方案说明由本地规则生成，并能导出到 JSON。
- 页面不再出现 SVG 平面预览、SVG 导出或旧的规则方案画布文案。

## 验收标准

- 用户可以完成“上传场地图 → 大图标注 → 调整参数 → AI 出图 → 查看说明”的完整流程。
- 标注动作只发生在放大后的场地图主窗口。
- 用户界面中没有 SVG 预览和 SVG 导出入口。
- AI 请求不依赖 SVG 作为中间产物。
- 方案说明在没有文本模型 API 的情况下也能本地生成。
- JSON 导出能够还原本次生成的核心输入和输出。
