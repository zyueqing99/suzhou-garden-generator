# 第二版原型图设计说明

## 背景

当前应用已经具备项目历史、场地图上传与标记、需求确认、规则 SVG 生成、AI 图像生成和导出能力。第二版原型图要求将这些能力重新组织为更接近专业景观方案工作台的界面：顶部流程导航、左侧项目历史、左中控制面板、中央方案画布、右侧方案解释。

## 目标

实现第二版前端原型，使用户打开应用后能直接看到完整的“苏式庭院景观概念方案生成器”工作台。界面应体现从场地解析到方案生成的 4 步流程，并突出中央平面预览和右侧方案说明。

## 非目标

- 不新增后端接口。
- 不改变 `GardenProject`、`GardenParameters`、`SiteMarkup`、`RequirementConfirmation` 的持久化结构。
- 不重写规则生成算法。
- 不把原型图中的所有按钮做成完整业务闭环；示例、帮助、保存项目等顶部按钮可以先作为视觉与可访问按钮保留。

## 信息架构

页面改为五个主要区域：

1. 顶部应用栏：展示品牌、产品名、简短副标题、示例/帮助/保存项目/导出按钮、用户身份入口。
2. 顶部流程条：展示“场地解析、需求确认、园林规则、方案生成”四步，前三步为已完成状态，第四步为当前状态。
3. 左侧项目历史：保留新建项目、打开项目、删除项目能力，项目卡展示名称、时间和缩略图式占位。
4. 左中控制面板：整合场地解析、需求确认、生成控制。保留上传地块图、核心需求展示、水景比例、山石比例、植物密度、视线箭头、标注、随机种子、生成方案、导出 PNG/SVG/JSON。
5. 中央方案区与右侧说明区：中央默认展示 SVG 平面图，带标签页、适应画布、缩放、重置和 SVG/AI 展示切换；右侧展示方案解释折叠项和输出内容清单。

## 组件策略

继续以 `GardenWorkspace` 作为主要工作台组件，不拆散业务状态。为了降低风险，第二版只在现有组件内新增小型展示组件与辅助函数，例如顶部栏、流程条、方案解释、生成控制。`ProjectHistory` 保持独立组件，但视觉改为原型图中的窄侧栏和项目卡样式。

## 交互策略

- “生成方案”继续调用现有 `handleGenerate`，递增 seed 并刷新规则平面。
- 导出 PNG、SVG、JSON 继续调用现有导出函数。
- 生成控制中的水景比例、山石比例、植物密度继续映射到现有参数。
- “视线箭头”和“标注”作为第二版原型开关展示，不在本次改变规则 SVG 输出。
- 中央 “SVG 平面 / AI 展示图” 切换保留按钮语义，本次默认展示 SVG 平面；AI 图像结果仍通过已有生成能力产生。

## 视觉方向

采用原型图的低饱和米白背景、深绿色主按钮、细边框、8px 以内圆角和密集但清晰的信息布局。页面更像方案生产工具，不做营销页。中央画布保留大面积平面图，右侧说明卡片避免过度装饰。

## 测试

先更新服务端渲染测试，覆盖第二版关键结构：

- 顶部品牌栏和四步流程存在。
- 左中控制面板包含场地解析、需求确认、生成控制。
- 中央方案区包含方案预览、标签页和 SVG 平面切换。
- 右侧方案解释和输出内容清单存在。
- 旧的核心能力文案仍可见：生成方案、导出 PNG、导出 SVG、导出 JSON。

最后运行完整测试和生产构建，并用本地 dev server 验证页面可打开。
